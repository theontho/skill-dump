# 1Password CLI sessions (op-session)

- Check `op-session status` first: exit 0 means the local lease is active, 2 means approval is pending, and 1 means inactive. Resume a pending approval; do not stop it or start another.
- Authenticate once with `op-session start` in an interactive terminal (over SSH it signs in with the account password in the terminal instead of desktop-app approval; `--cli`/`--app` override), or `op-session start --terminal` from an agent. The default lease is one hour. Longer leases require explicit authorization; use `start -d 12h`, or `extend -d 12h` (which extends an active lease or starts one). Route every subsequent CLI call, including scripts, through `op-session OP_ARGUMENT ...` or `op-session run -- OP_ARGUMENT ...`. The legacy `op-session exec op ...` form remains supported.
- Verify reuse with two non-secret `op-session whoami` calls from separate fresh shells. Status alone does not prove vault access. Keep the grant throughout related work; stop a session you started when that work ends, but leave pre-existing sessions available unless the user asks to stop them.
- For CLI-only sign-in without the desktop, the person runs `op-session signin` (alias for `start --cli`) in their own terminal. First-time account setup and password prompts stay in that terminal. `OP_ACCOUNT` or legacy `OP_SESSION_ACCOUNT` selects the account; `run -- op ...` and `exec op ...` remain compatible with older callers.
- On macOS, enable **Keep 1Password in the menu bar** and leave the app running. App lock, quit or restart can revoke CLI authorization; never weaken security locks. Keepalives use the authorized foreground pane, not a background process without a TTY.
- Diagnose failures from stderr, `op-session status`, `op-session logs` (authentication stages and stderr only), and `{{HOME}}/.local/state/copilot-agent-sessions/audit.log` before requesting another approval. Never print secrets as diagnostics.
- Prefer `op-session run -- op run -- COMMAND ...` with `op://` environment references. If `op read` is necessary, consume its output inside the receiving script, never in tool output, command-line arguments, tracing or credential-bearing logs. Never ask for passwords, tokens or session keys in chat.
