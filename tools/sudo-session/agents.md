# Privileged sessions (sudo-session)

- For repeated trusted administrative work, authenticate in a private SSH terminal with `ssh -t {{USER}}@{{HOST}} sudo-session start --ssh`, then detach with Ctrl-b, d. This retains a normal audited sudo credential in a dedicated tmux PTY (default one hour), without a desktop popup or a passwordless sudoers grant. A user-requested longer session can use `start -d 12h` or `extend -d 12h` for at least twelve hours remaining; either extends an active session using its credential, or starts a new one (needing authentication) when none is active. Shortening a lifetime requires stopping and authenticating again. Never request or send the password through agent chat. `sudo-session start` also works directly in a private local terminal. Run `sudo-session --help` for the full command reference.
- Run privileged commands from any fresh agent shell with `sudo-session run -- COMMAND [ARG ...]` (or `sudo-session COMMAND [ARG ...]`). Do not invoke mutating privileged commands bare.
- Check or revoke access with `sudo-session status` and `sudo-session stop`.
- Keep untrusted downloaded code outside privileged sessions and never execute it through `sudo-session`.
- On macOS or from a non-interactive agent, use `sudo-session start --terminal` to open a real terminal for the person's approval. Check `sudo-session status` first: exit 2 means approval is pending in the existing terminal, not permission to restart it. Keep one grant throughout related work, then stop once.
